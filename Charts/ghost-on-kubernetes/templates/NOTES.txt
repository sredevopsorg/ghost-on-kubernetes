Thank you for installing {{ .Chart.Name }} {{ .Chart.Version }} (Ghost {{ .Chart.AppVersion }}).

Release {{ .Release.Name }} lives in namespace {{ .Release.Namespace }}.

{{- if .Values.ingress.enabled }}

1. Ghost will be available once the Ingress controller picks up the routes:
{{- range .Values.ingress.hosts }}
   https://{{ .host }}
{{- end }}

{{- if .Values.ingress.tls.enabled }}
{{- if eq .Values.ingress.tls.mode "certManager" }}
   TLS certificates are being provisioned by cert-manager and land in secret
   {{ include "ghost-on-kubernetes.fullname" . }}-tls-cert. This takes a few minutes.
{{- else if eq .Values.ingress.tls.mode "both" }}
   TLS secret: {{ .Values.ingress.tls.secretName }}
   The cert-manager annotation is applied as well, so cert-manager may rotate that secret.
{{- else }}
   TLS secret: {{ .Values.ingress.tls.secretName }}
{{- end }}
{{- if and (eq .Values.ingress.tls.mode "manual") (not .Values.ingress.tls.certificate) }}

   NOTE: mode is "manual" but ingress.tls.certificate is empty, so this chart did
   not create {{ .Values.ingress.tls.secretName }}. Create it yourself, otherwise TLS never works:
   kubectl create secret tls {{ .Values.ingress.tls.secretName }} --cert=tls.crt --key=tls.key -n {{ .Release.Namespace }}
{{- end }}
{{- end }}
{{- else }}

1. Reach Ghost through the Service:

   kubectl port-forward -n {{ .Release.Namespace }} svc/{{ include "ghost-on-kubernetes.fullname" . }}-service {{ .Values.service.port }}:{{ .Values.service.port }}

   Then visit: http://localhost:{{ .Values.service.port }}
{{- end }}

2. Watch the rollout:

   kubectl rollout status -n {{ .Release.Namespace }} deployment/{{ include "ghost-on-kubernetes.fullname" . }}

3. Pods of this release:

   kubectl get pods -n {{ .Release.Namespace }} -l app.kubernetes.io/instance={{ .Release.Name }}
{{- if .Values.mysql.enabled }}

4. MySQL runs in this release. Database: {{ .Values.mysql.auth.database }}

   kubectl port-forward -n {{ .Release.Namespace }} svc/{{ include "ghost-on-kubernetes.fullname" . }}-mysql-service {{ .Values.service.mysql.port }}:{{ .Values.service.mysql.port }}
{{- else }}

4. Ghost connects to the external MySQL at {{ .Values.mysql.external.host }}:{{ .Values.mysql.external.port }}, database {{ .Values.mysql.external.database }}.
{{- end }}
{{- if .Values.valkey.enabled }}

5. Valkey caching runs in this release at {{ include "ghost-on-kubernetes.fullname" . }}-valkey-service:{{ .Values.service.valkey.port }}.
   Authentication: {{ if .Values.valkey.auth.enabled }}required{{ else }}disabled, do not expose it outside the cluster{{ end }}
{{- else if .Values.valkey.external.enabled }}

5. Ghost caches through the external Valkey at {{ .Values.valkey.external.host }}:{{ .Values.valkey.external.port }}.
{{- else }}

5. Application caching is disabled. Enable valkey.enabled for a faster site.
{{- end }}

6. Follow the logs:

   kubectl logs -n {{ .Release.Namespace }} -l app.kubernetes.io/instance={{ .Release.Name }} -c ghost -f

7. Verify the release end to end:

   helm test {{ .Release.Name }} -n {{ .Release.Namespace }}

8. Finish the Ghost admin setup in your browser, then sign in at {{ .Values.ghost.adminUrl | default .Values.ghost.url }}/ghost/.

{{- if and .Values.mysql.enabled .Values.mysql.initContainer.enabled }}

NOTE: the MySQL pod starts with a root init container that chowns its data
directory, which the restricted Pod Security Standard rejects. Set
mysql.initContainer.enabled=false to rely on podSecurityContext.fsGroup instead.
{{- end }}
{{- if not .Values.persistence.ghost.enabled }}

WARNING: persistence.ghost.enabled is false. Ghost content lives in an emptyDir:
uploads, themes and settings are lost on every pod restart. Fine for a throwaway
install, not for a site with content.
{{- end }}
{{- if and .Values.mysql.enabled (not .Values.persistence.mysql.enabled) }}

WARNING: persistence.mysql.enabled is false. The database lives in an emptyDir and
all data is lost on every MySQL pod restart.
{{- end }}
{{- $rolling := dig "rollingUpdate" dict .Values.strategy }}
{{- if and .Values.persistence.ghost.enabled (eq .Values.persistence.ghost.accessMode "ReadWriteOnce") (ne .Values.strategy.type "Recreate") (gt (int (dig "maxSurge" 0 $rolling)) 0) (not .Values.autoscaling.enabled) }}

WARNING: a ReadWriteOnce content volume rolls out with maxSurge={{ dig "maxSurge" 0 $rolling }}
and maxUnavailable={{ dig "maxUnavailable" 0 $rolling }}, which can stall an update: the surge pod
cannot attach the volume on another node and the old pod is kept until the new one
is ready. Use strategy.type=Recreate, or ReadWriteMany storage.
{{- end }}
